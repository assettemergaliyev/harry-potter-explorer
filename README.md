# 🪄 Путеводитель по Хогвартсу

Интерактивное веб-приложение для исследования волшебной вселенной Гарри Поттера.

Пользователь может изучать факультеты Хогвартса, просматривать каталог персонажей, искать персонажей по имени, изучать заклинания, добавлять любимых героев в избранное и даже общаться с персонажами с помощью LLM.

## 🌐 Демо

Production-версия приложения:

https://harry-potter-explorer-beta.vercel.app

## ✨ Возможности

### Факультеты Хогвартса

Отдельная страница с четырьмя факультетами:

- Гриффиндор
- Слизерин
- Когтевран
- Хаффлпафф

Для каждого факультета отображаются его цвета, символика, основные качества и краткое описание.

### Каталог персонажей

Данные о персонажах загружаются из Harry Potter API через собственный server-side API приложения.

Для каждого персонажа отображаются:

- изображение;
- имя;
- факультет;
- патронус.

Каталог поддерживает поиск по имени и пагинацию.

### Детальная страница персонажа

Каждый персонаж имеет собственную динамическую страницу `/characters/[id]`.

На ней можно увидеть дополнительную информацию:

- факультет;
- дату рождения;
- вид;
- происхождение;
- патронуса;
- актёра;
- статус персонажа;
- характеристики волшебной палочки.

### ❤️ Избранные персонажи

Персонажа можно добавить в избранное.

Список избранных хранится в `localStorage`, поэтому сохраняется после обновления страницы без необходимости регистрации пользователя.

В каталоге также доступен режим «Только избранные».

### 📖 Каталог заклинаний

Дополнительно реализован каталог известных заклинаний с описанием и поиском по названию.

### 🤖 Магическая беседа

На детальной странице персонажа можно задать ему вопрос и получить ответ с помощью LLM.

Приложение передаёт модели контекст выбранного персонажа — имя, факультет, происхождение, патронуса и характеристики волшебной палочки — и формирует инструкции для ролевого ответа.

Таким образом, один и тот же компонент работает динамически для разных персонажей.

Все обращения к LLM выполняются только с серверной части приложения. API-ключ не передаётся клиенту и хранится в environment variables.

## 🏗️ Архитектура

Основной поток получения персонажей:

```text
Browser
   ↓
Next.js /api/characters
   ↓
Harry Potter API
   ↓
Next.js
   ↓
Browser
```

Поток LLM-чата:

```text
Browser
   ↓
POST /api/chat
   ↓
Next.js Server
   ↓
OpenAI API
   ↓
Next.js Server
   ↓
Browser
```

Внешние сервисы не вызываются напрямую из клиентской части приложения.

## 💡 Почему выбран этот стек

### Next.js

Next.js позволяет реализовать frontend и server-side API в одном проекте.

Это особенно удобно для данного задания, поскольку внешние API должны вызываться с серверной части. API Routes позволяют скрыть детали взаимодействия с внешними сервисами и не раскрывать секретные ключи клиенту.

### TypeScript

TypeScript используется для типизации данных персонажей, API responses и props компонентов. Это уменьшает количество потенциальных ошибок при работе со структурированными данными.

### Tailwind CSS

Tailwind CSS позволил быстро создать адаптивный интерфейс и сохранить единый визуальный стиль приложения без необходимости создавать большое количество отдельных CSS-файлов.

### OpenAI API

OpenAI API используется для бонусной функции общения с персонажами. LLM получает динамический контекст выбранного персонажа и отвечает на русском языке в формате ролевого диалога.

### Vercel

Vercel выбран благодаря простой интеграции с Next.js и GitHub. Каждый push в ветку `main` автоматически запускает новый production deployment.

## 🔌 Работа с Harry Potter API

В приложении используется:

`https://hp-api.onrender.com/`

Frontend не обращается к этому API напрямую.

Для каталога используется собственный endpoint:

```text
GET /api/characters
```

Он получает данные из внешнего API, выполняет поиск и пагинацию и возвращает подготовленный ответ frontend-приложению.

Пример:

```text
/api/characters?search=harry&page=1&limit=12
```

Для детальной страницы персонажа запрос к внешнему API выполняется на серверной стороне Next.js.

## 🤖 Работа с LLM

Для общения с персонажами используется собственный server-side endpoint:

```text
POST /api/chat
```

Frontend передаёт сообщение пользователя и данные выбранного персонажа.

Server-side route формирует инструкции для LLM с учётом контекста персонажа и только после этого обращается к OpenAI API.

API key хранится в переменной окружения:

```text
OPENAI_API_KEY
```

Файл `.env.local` исключён из Git через `.gitignore`.

## 🚀 Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/assettemergaliyev/harry-potter-explorer.git
```

### 2. Перейти в папку проекта

```bash
cd harry-potter-explorer
```

### 3. Установить зависимости

```bash
npm install
```

### 4. Создать `.env.local`

В корне проекта создать файл:

```text
.env.local
```

и добавить:

```env
OPENAI_API_KEY=your_openai_api_key
```

Без API key основная функциональность приложения продолжит работать, но LLM-чат будет недоступен.

### 5. Запустить development server

```bash
npm run dev
```

После запуска приложение будет доступно по адресу:

```text
http://localhost:3000
```

## 🧭 Процесс проектирования и разработки

Разработка велась итеративно — от минимально работающего интерфейса к дополнительным возможностям.

### Этап 1 — базовый интерфейс

Сначала была создана структура приложения, навигация, главная страница и страница факультетов.

### Этап 2 — динамические данные

После создания базового интерфейса был интегрирован Harry Potter API.

Затем были реализованы каталог персонажей, поиск, пагинация и состояния загрузки/ошибок.

### Этап 3 — deployment

После реализации обязательной функциональности приложение было опубликовано на Vercel и проверено в production.

### Этап 4 — расширение приложения

После выполнения основных требований были добавлены:

- детальная страница персонажа;
- избранные персонажи;
- фильтр избранного;
- каталог заклинаний;
- LLM-чат с персонажами.

Такой подход позволил сначала получить полностью работоспособный MVP, а затем безопасно расширять его бонусными возможностями.

## 🌟 Уникальные подходы

### Character-aware LLM chat

Вместо отдельного заранее настроенного чата только с одним персонажем был реализован универсальный компонент.

При открытии персонажа его данные динамически передаются LLM:

```text
Character
   ↓
name
house
species
ancestry
patronus
wand
   ↓
Dynamic LLM instructions
```

Поэтому один механизм позволяет общаться с разными персонажами без создания отдельной логики для каждого из них.

### Server-side integration

Взаимодействие с внешними сервисами вынесено на серверную сторону. Это позволяет контролировать API-запросы и не раскрывать секретные credentials в браузере.

### Progressive enhancement

Проект строился от обязательного MVP к дополнительным функциям. Каждый крупный этап фиксировался отдельными Git commits и проверялся до перехода к следующему.

## ⚖️ Компромиссы

Проект выполнялся в ограниченный срок, поэтому приоритет был отдан полностью работающему end-to-end решению вместо максимального количества функций.

### localStorage вместо базы данных

Избранные персонажи хранятся в `localStorage`.

Преимущества:

- не требуется регистрация;
- быстрое и простое решение;
- данные сохраняются после обновления страницы.

Ограничение: избранное привязано к конкретному браузеру и устройству.

### Пагинация вместо infinite scroll

Для каталога выбрана обычная пагинация. Она проще, предсказуемее для пользователя и позволяет явно продемонстрировать взаимодействие frontend и server-side API через параметры `page` и `limit`.

### Без отдельной базы данных

Интеграция с Supabase/Firebase рассматривалась как возможное развитие проекта, однако в рамках time-box приоритет был отдан LLM-интеграции, deployment и качеству основной пользовательской функциональности.

## ⚠️ Известные ограничения

- Некоторые записи Harry Potter API не содержат изображения, факультет или патронуса.
- Список избранного хранится только локально в браузере.
- Режим «Только избранные» работает среди персонажей текущей загруженной страницы.
- LLM-чат требует действующего OpenAI API key и доступной API-квоты.
- Ответы LLM генерируются моделью и могут не всегда полностью соответствовать канону вселенной.
- История LLM-диалога между вопросами в текущей версии не сохраняется.
